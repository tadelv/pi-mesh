# Session resume — implementation plan

Scope: implement accepted ADR 0019; do not attach to an external TUI, guess liveness from a file, or add process machinery to the control plane. Installed Pi 0.87.1 verification and the concurrent-writer probe are recorded in the ADR. `--session <validated file>` is the Pi CLI mechanism; `-r` opens an interactive picker and is not suitable for the agent's RPC mode.

1. **Agent seam — red/green.** Add a gated `session.resume { session_id, acknowledge_concurrent_writers: true }` skill using the existing JobManager, Pi RPC spawner and local session store. Resolve exactly one on-disk session (never accept a path from the caller), validate its cwd and path, refuse a known running/starting job or concurrent resume of the same file, and return `{ job_id, pid, session_id }` for the newly managed Pi process. Test exact-file reuse, promptable running job, unknown/ambiguous/outside-workspace session, opt-out, and two simultaneous requests; break at least one safety guard to prove the named test fails. Update agent-card capability and `docs/PROTOCOL.md`.
2. **Dashboard seam — red/green.** For a verified selected session with no running job and eligible execution transport/capability, show Resume with ADR 0019's full data-corruption warning and an initially unchecked confirmation required for *each* attempt. No implicit prompt or automatic resume. Block duplicate submissions, preserve the selected-session owner across async results, show agent refusal distinctly from transport errors, and Sync the agent's job table after success before offering the ordinary Prompt. Browser test confirms warning and checkbox are prerequisites, and an active job offers Prompt rather than Resume; mutate the checkbox guard to make its clause fail.
3. **Review and validation.** Fresh a-team reviewer checks the diff against ADRs 0008, 0013, 0015, 0016 and 0019 and identifies tests that could pass when safeguards are removed. Parent validates `pnpm -r build`, `pnpm typecheck`, `pnpm -r --if-present test`, `pnpm test:browser`, `pnpm -r --if-present lint`, `pnpm format:check`, `git diff --check`, and fixes any blocker before publication. Update README/SECURITY/PRODUCT/DESIGN only where the public claim changes.
4. **Publish and prove.** Parent commits and pushes after review, checks CI, builds the committed control-plane image in Portainer stack 43 on `apollo.local` without replacing its database volume, and updates the opted-in agent on `devpi` to the matching revision. Verify a real saved, non-active test session resumes with the same ID and is promptable; do not try to resume an active TUI file just to demonstrate the warning. Record the observed result and remaining limit in `README.md`'s "Verified on real hardware" section. Never print the Portainer key or dashboard token.
